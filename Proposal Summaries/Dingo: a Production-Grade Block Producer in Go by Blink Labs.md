## Simple Summary

This proposal asks Cardano to give **6.9 million ADA** to Blink Labs so they can spend **one year** finishing a new Cardano node called **Dingo**.

A **node** is one of the main pieces of software that helps run the blockchain.

Right now, Cardano mainly depends on one node software stack for block production. This proposal argues that having another serious node implementation would make Cardano safer and more resilient, because the whole network would not be relying so heavily on one codebase. The trade-off is simple: Cardano would spend treasury money now in exchange for a potentially stronger network later.  

---

## What they are asking for

Blink Labs wants treasury funding to:

* finish Dingo so it can eventually run on mainnet
* make it strong enough for real-world use
* add support for future Cardano upgrades
* pay for a security audit
* improve documentation and operations

So the request is basically:

**“Give us funding now so we can turn Dingo from a strong work-in-progress into a production-ready Cardano node.”**

---

## Why they say this matters

Their main argument is:

**Cardano should not depend too much on a single node implementation.**

If only one main node software is used everywhere, then a serious bug in that software could affect the whole network.

They are saying Dingo would help by giving Cardano another real option.

In plain terms:

* **one node implementation** = more concentration of risk
* **multiple node implementations** = less chance that one bug hurts everyone at once

That is the biggest reason behind this proposal.

---

## What happens if the proposal passes

If voters approve it:

* Blink Labs gets the funding
* they continue building Dingo full-time for 12 months
* Cardano may end up with a second serious node implementation
* the treasury balance goes down by **6.9 million ADA**

Best-case outcome:

* Dingo becomes ready for mainnet block production
* SPOs eventually get another node option
* Cardano becomes more resilient

---

## What happens if the proposal fails

If voters reject it:

* Blink Labs does not get this treasury money
* Dingo development likely continues more slowly
* Cardano stays more dependent on existing node software
* the treasury keeps the 6.9 million ADA

So the “no” case is not “Dingo disappears.”
It is more like:

**“This work probably continues slower, with less certainty, and Cardano keeps relying on the current setup for longer.”**

---

## What non-technical people should focus on

A non-technical voter does **not** need to understand all the node details.

The real decision is this:

### Option A: Vote yes

“Use treasury money now to reduce long-term infrastructure risk.”

### Option B: Vote no

“Keep the treasury money and accept that node diversity may arrive later, slower, or not at all.”

That is the core trade-off.

---

## The good side of the proposal

Reasons someone might support it:

* it tries to reduce Cardano’s dependence on one main node stack
* it supports more competition and diversity in core infrastructure
* it could make Cardano more robust over time
* Blink Labs shows they already built substantial work, not just an idea
* the proposal includes reporting, oversight, escrow, and an audit plan

---

## The risk side of the proposal

Reasons someone might hesitate:

* **6.9 million ADA is a large treasury withdrawal**
* finishing a node is hard, and production-readiness is harder than building features
* success is not guaranteed
* even if Dingo becomes technically solid, real adoption by operators is still not guaranteed
* some milestone language is ambitious and not always easy for ordinary voters to verify

So this is not a low-risk proposal.
It is a **big infrastructure bet**.

This proposal is asking Cardano voters:

**“Should the treasury spend 6.9 million ADA to help create a real second Cardano node, so the network is less dependent on one main implementation?”**
